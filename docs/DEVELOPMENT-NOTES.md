# PocketDesk OS 개발 기록

## 1. App.tsx 기능 분리

`App.tsx`는 데스크톱 셸, 창 관리자, 앱 간 상태 연결만 담당합니다. Edge, 파일 탐색기, 내 PC, 휴지통, 메모장, 그림판, 계산기, 지뢰찾기와 설정은 `src/apps/`의 독립 모듈로 분리했습니다.

앱 이름, 아이콘, 기본 창 크기는 `src/apps/metadata.ts`, 공통 타입은 `src/types.ts`, 표시 형식은 `src/utils/format.ts`가 소유합니다. 새 앱을 추가할 때 셸 내부에 큰 컴포넌트를 다시 만들지 않아도 됩니다.

## 2. IndexedDB 파일 시스템 안전성

가상 파일 시스템은 `src/vfs/storage.ts`에서 직렬화된 쓰기 큐와 단일 읽기·쓰기 트랜잭션을 사용합니다. 기존 항목 삭제와 새 스냅샷 저장이 하나의 트랜잭션에서 처리되므로 중간 실패가 반쪽 저장 상태를 남기지 않습니다.

데이터베이스 버전 2는 `entries`와 `meta` 저장소, 부모 폴더와 종류 인덱스, 스키마 버전과 항목 수를 기록합니다. 저장 전에는 중복 ID, 항목 수와 전체 콘텐츠 크기를 검사합니다.

ZIP 복원은 앱·포맷 버전, 파일 크기, 압축 방식, 암호화 여부, CRC, UTF-8, JSON 구조와 중복 ID를 검증합니다. 검증이 끝나기 전에는 현재 파일을 변경하지 않습니다.

## 3. iframe 차단 사이트 브라우저 UX

외부 사이트의 `X-Frame-Options`와 CSP는 웹 앱이 우회할 수 없습니다. PocketDesk Edge는 iframe 허용 사이트를 창 안에서 열고, 차단 가능성이 높은 호스트는 읽기 보기를 우선 사용합니다.

빈 화면이 생기면 Edge 메뉴의 **페이지 표시 문제**에서 복구 화면을 열 수 있습니다. 사용자는 같은 창의 읽기 보기로 전환하거나 마지막 수단으로 새 탭을 선택합니다. 주소, 뒤로·앞으로 기록과 보기 모드는 함께 유지됩니다.

## 4. PWA 오프라인과 업데이트

서비스 워커 v4는 설치 시 HTML에서 빌드된 해시 JS·CSS를 찾아 정적 앱 셸과 함께 캐시합니다. 문서 탐색은 네트워크 우선, 해시 자산은 캐시 우선, 이미지와 나머지 동일 출처 자산은 stale-while-revalidate 전략을 사용합니다.

새 서비스 워커는 설치 직후 작업 중인 페이지를 강제로 교체하지 않습니다. 대기 상태를 감지하면 Windows 알림 형태의 업데이트 안내가 나타나며, **지금 다시 시작**을 선택했을 때만 `SKIP_WAITING`을 전달하고 새 버전으로 다시 로드합니다.

이전 PocketDesk 캐시만 정리하므로 같은 출처의 다른 앱 캐시는 삭제하지 않습니다. 온라인 복귀, 탭 재활성화와 1시간 주기로 업데이트를 확인합니다.

## 5. 실제 폴더 계층과 탐색기

가상 파일의 `parentId`를 실제 부모 폴더 관계로 사용합니다. 바탕 화면 아래에 문서, 사진, 게임 기본 폴더를 두고, 기존 IndexedDB 데이터는 파일 종류에 맞는 기본 폴더로 한 번만 안전하게 이동합니다. 잘못된 부모와 순환 경로는 바탕 화면으로 복구합니다.

파일 탐색기는 현재 폴더의 직계 자식만 표시합니다. 뒤로, 앞으로, 위로, 주소 경로, 폴더 더블클릭과 `Alt + 화살표` 탐색이 같은 기록을 사용합니다. 새 폴더와 문서는 현재 위치에 생성되며 복사와 드래그 이동은 하위 폴더 전체를 보존합니다.

폴더를 삭제하면 모든 하위 항목에 같은 휴지통 루트 ID를 기록합니다. 휴지통에는 최상위 삭제 항목 하나만 보이지만 복원·영구 삭제는 전체 트리에 적용됩니다. 원래 부모가 사라졌다면 바탕 화면으로 복원하고 같은 이름이 있으면 충돌 없는 이름을 만듭니다.

## 6. 탐색기 다중 창과 공용 파일 대화상자

파일 탐색기는 앱 단위 싱글턴 예외로 관리합니다. 새 창 버튼을 누르면 별도 창 ID와 탐색 기록을 가진 인스턴스가 생성되며, 작업 표시줄은 같은 앱의 창을 하나로 묶어 개수와 창별 미리보기를 표시합니다. 일반 실행은 가장 위에 있는 기존 탐색기 창을 활성화합니다.

`src/components/FileDialog.tsx`는 메모장과 그림판이 함께 쓰는 열기·저장 대화상자입니다. 뒤로, 앞으로, 위로, 주소 경로, 검색, 새 폴더, 파일 종류 필터, 확장자 자동 추가와 같은 이름 덮어쓰기 확인을 한곳에서 처리합니다.

메모장은 TXT, 그림판은 PNG 항목을 IndexedDB 가상 파일 시스템에서 직접 열고 저장합니다. 새 파일과 덮어쓰기는 기존 파일 모델을 그대로 사용하므로 파일 탐색기, 휴지통, ZIP 백업에서도 같은 항목으로 보입니다. `Ctrl+O`, `Ctrl+S`, `Ctrl+Shift+S`는 활성 창의 앱에만 전달됩니다.

## 7. 데스크톱 셸 모듈 분리

`App.tsx`는 5,365줄까지 자랐고 창 관리자, 작업 표시줄, 시작 메뉴, 컨텍스트 메뉴, 사운드 합성, 검색 랭킹이 한 파일에 섞여 있었습니다. 이를 `src/shell/`로 분리했습니다.

`types.ts`와 `constants.ts`가 셸 타입·상수를, `appCatalog.ts`가 앱 등록을, `windowState.ts`·`windowGeometry.ts`가 창 상태와 스냅 계산을, `desktopLayout.ts`가 아이콘 격자·선택 사각형 계산을, `startSearch.ts`가 시작 메뉴 검색과 실행 명령 해석을, `vfsBootstrap.ts`가 초기 파일 로드와 마이그레이션을, `sound.ts`가 오실레이터 합성을 소유합니다. 셸 UI는 `src/shell/components/`로 옮겼습니다.

`App.tsx`는 약 2,100줄로 줄었고 상태 연결과 창 오케스트레이션만 담당합니다. 분리된 순수 모듈은 브라우저 없이 단위 테스트할 수 있습니다.

## 8. 명령 프롬프트

명령 해석은 `src/shell/commandShell.ts`의 `runShellCommand(input, context)` 순수 함수입니다. 현재 폴더 ID, 파일 목록, 실행 중인 창 목록을 받아 출력 줄 배열과 효과 배열만 반환하며 상태를 직접 바꾸지 않습니다. `TerminalApp`이 그 효과를 기존 파일 시스템 콜백으로 적용합니다.

경로 해석은 `\`와 `/`를 모두 받고 `.`, `..`, `~`, `C:\Users\PocketDesk\Desktop` 접두사를 처리하며 이름은 대소문자를 구분하지 않습니다. 존재하지 않는 구간이 나오면 즉시 실패해 잘못된 폴더에 파일을 만들지 않습니다.

`echo 내용 > 파일`과 `>>`는 따옴표 밖의 첫 `>`만 리디렉션으로 인식합니다. 파일 쓰기는 메모장·그림판이 쓰는 것과 같은 저장 경로를 사용하므로 셸에서 만든 파일이 파일 탐색기, 휴지통, ZIP 백업에서 동일한 항목으로 보입니다.

`tasklist`의 PID는 창 목록의 순서 기반이고 메모리 값은 창 ID 해시에서 파생합니다. 다시 호출해도 같은 값이 나오도록 난수를 쓰지 않았습니다.

## 9. 가상 데스크톱

`WindowInstance.desktopIndex`가 창이 속한 데스크톱을 기록하고 localStorage에 함께 저장됩니다. 데스크톱 개수는 저장값과 실제 창의 최댓값 중 큰 쪽으로 계산하므로, 저장값이 손상돼도 창이 보이지 않는 데스크톱에 갇히지 않습니다.

창 레이어, 작업 표시줄, `Alt+Tab`, 바탕 화면 보기는 모두 현재 데스크톱의 창만 다룹니다. 다른 데스크톱의 창에 포커스를 주면 그 데스크톱으로 함께 전환합니다. 데스크톱을 닫으면 그 안의 창을 왼쪽 데스크톱으로 넘기고 뒤쪽 인덱스를 하나씩 당깁니다.

## 10. 이름 길이 상한 처리

48자 상한을 중복 검사 **이후에** 적용하던 버그가 있었습니다. 48자짜리 이름이 이미 있는 폴더에서 같은 이름을 요청하면 후보 `이름 (2)`가 잘려 원본과 같아지고, 확장자 중간이 잘리기도 했습니다.

이제 `buildCappedVfsName`이 접미사와 확장자 길이를 먼저 확보하고 base만 줄여 후보를 만든 뒤 중복을 검사합니다. 절단은 UTF-16 코드 유닛이 아니라 코드 포인트 경계에서 멈추므로 이모지가 반쪽만 남지 않습니다.

## 11. 단일 번들 유지 이유

서비스 워커는 `index.html`에서 참조된 `/assets/` 자산만 찾아 사전 캐시합니다. 앱별로 코드를 분할하면 지연 로드 청크가 HTML에 나타나지 않으므로, 사용자가 온라인에서 한 번 열어보지 않은 앱은 오프라인에서 동작하지 않습니다.

오프라인 보장이 번들 크기보다 중요하다고 판단해 데스크톱 전체를 단일 번들로 유지합니다. `vite.config.ts`의 `chunkSizeWarningLimit`은 이 결정에 맞춰 올려 두었으며, 나중에 분할하려면 서비스 워커의 자산 수집 방식을 먼저 바꿔야 합니다.

## 12. 셸 확장: 변수, 와일드카드, 파이프, 배치

명령 한 줄은 **확장 → 파이프 분리 → 첫 단계 실행 → 하위 단계 필터** 순으로 처리됩니다.

`%NAME%` 치환은 파싱 **전에** 일어나므로 `cd %PROJECT%`처럼 변수가 경로 자리에 와도 동작합니다. 알 수 없는 이름은 지우지 않고 그대로 둡니다. 사용자 변수가 내장 변수를 가릴 수 있습니다.

파이프의 하위 단계는 텍스트만 변형하며 부수 효과를 만들지 않습니다. 첫 단계만 효과를 소유하므로 `md 폴더 | find 폴더`는 폴더를 한 번만 만듭니다. 하위 단계로는 cmd에서 표준 입력을 읽는 `find`, `findstr`, `sort`, `more`만 허용합니다. `find`가 첫 단계면 가상 파일 시스템을 검색하고, 하위 단계면 앞 단계의 출력을 거릅니다.

와일드카드는 정규식으로 변환하기 전에 메타문자를 이스케이프하므로 `a+b.txt` 같은 이름이 패턴처럼 동작하지 않습니다. `del`, `copy`, `move`는 파일 대상이라 매치에서 폴더를 제외합니다.

`^`는 cmd와 같이 다음 한 글자를 리터럴로 만듭니다. 리디렉션과 파이프 분리기가 이스케이프된 문자를 건너뛴 뒤, 남은 `^`를 제거합니다. 이 이스케이프가 없으면 `echo`로 `>`를 배치 파일에 쓸 수 없어 배치 파일이 파일을 만들지 못합니다.

## 13. 배치 파일이 앞 줄의 결과를 보는 방법

명령 엔진은 순수 함수라 효과를 직접 적용하지 않습니다. 따라서 배치의 두 번째 줄이 첫 줄이 만든 폴더를 보려면 그 사이에 실제 상태 반영이 끝나야 합니다.

엔진은 `runScript` 효과로 실행할 줄 목록만 넘기고, `TerminalApp`이 큐에 쌓아 **커밋당 한 줄씩** 실행합니다. 큐가 줄어들 때마다 리렌더가 일어나고 다음 줄은 갱신된 `desktopItems`를 받습니다. 엔진에 가상 파일 시스템 시뮬레이션을 넣지 않고도 `md 백업` 다음 줄의 `echo x > 백업\로그.txt`가 성공합니다.

## 14. 저장 검증과 오류 전달

`persistVfsEntries`는 항목 수·중복 ID·콘텐츠 크기를 검사한 뒤 쓰기 큐에 넣습니다. 검증은 호출 시점에 즉시 수행해 이후 배열 변형이 큐에 들어간 스냅샷에 닿지 않게 하지만, 실패는 `Promise.reject`로 돌려줍니다. 이전에는 동기 예외였는데, 호출부가 `.catch()`로 저장 실패 알림을 띄우고 있어 한도 초과가 알림 대신 처리되지 않은 오류로 새어 나갔습니다.

바이트 합산은 항목마다 `Blob`을 만들지 않고 모듈 단위 `TextEncoder` 하나를 재사용합니다.

## 15. 하나의 시스템 클립보드

파일 탐색기와 바탕 화면이 각자 클립보드 상태를 들고 있어서, 탐색기에서 복사한 뒤 바탕 화면에 붙여넣으면 아무 일도 일어나지 않았습니다. 클립보드를 셸이 소유하는 `{ itemIds, mode }` 하나로 합쳤습니다.

잘라내기는 붙여넣을 때 이동으로 처리하고 클립보드를 비웁니다. 바탕 화면에 붙여넣는 경우에는 `moveVfsEntries`가 `showOnDesktop`을 꺼 버리므로 이동 직후 다시 켜고 아이콘 위치를 지정합니다.

## 16. 기본 앱과 `activateVfsEntry`

`openVfsEntry`는 파일 형식에 따라 어떤 앱을 열지 결정합니다. PNG를 사진 앱에 연결하자 그림판에서 저장할 때마다 사진 앱으로 튀는 문제가 생겼습니다. 저장은 "이 파일을 여는 행위"가 아니기 때문입니다.

그래서 `activateVfsEntry`를 나눴습니다. 이미 그 파일을 다루고 있는 앱 안에서 대상 항목만 현재 항목으로 바꾸고 앱 라우팅은 하지 않습니다. 그림판·메모장의 저장/열기 대화상자와 사진 앱의 편집 버튼이 이 경로를 씁니다.

기본 앱 지정은 확장자 → `AppId` 맵으로 localStorage에 저장하고 `openVfsEntry`에서만 참조합니다. 저장된 값에 알 수 없는 확장자나 존재하지 않는 앱 ID가 들어 있으면 무시하므로, 레지스트리 편집기에서 손으로 고친 값이 파일 형식을 빈 곳으로 보내지 않습니다.

## 17. 실제 데이터로 동작하는 시스템 앱

이벤트 뷰어는 로그를 만들어 내지 않고 이미 저장된 사실에서 파생합니다. 항목별 `createdAt`, `createdAt`과 다른 `updatedAt`, `trashedAt`, 그리고 열린 창 목록이 각각 한 행이 됩니다. 창에는 열린 시각이 저장돼 있지 않으므로 그 행만 "관찰 시각"으로 구분해 표시합니다.

레지스트리 편집기는 데스크톱이 실제로 설정을 저장하는 `localStorage`를 직접 읽고 씁니다. 하이브 트리는 런타임에 존재하는 `pocket-desk-` 키를 열거해 만들기 때문에, 나중에 기능이 추가돼 키가 늘어도 코드를 고치지 않고 나타납니다. 쓰기·삭제는 접두사를 다시 검사합니다.

## 18. 컴포넌트 테스트 환경

단위 테스트 기본 환경은 `node`입니다. 컴포넌트 테스트만 파일 첫 줄의 `// @vitest-environment jsdom` 주석으로 jsdom을 선택합니다. 순수 로직 테스트가 불필요하게 DOM을 띄우지 않도록 전역 환경을 바꾸지 않았습니다.

## 19. 이미지를 저장할 때만 바이트로 바꾸는 이유

그림은 모델에서 `data:image/png;base64,...` 문자열입니다. 그림판이 만드는 형태이고, ZIP 백업이 JSON으로 직렬화하는 형태이며, `<img src>`가 그대로 받는 형태입니다. 다만 base64는 원본 PNG보다 1/3 더 큽니다.

전체를 `Blob`으로 바꾸면 백업 JSON이 조용히 `{}`로 깨지고, ZIP 포맷·검증·앱 렌더링까지 전부 손대야 합니다. 그래서 변환을 **IndexedDB 경계 한 곳**으로 가뒀습니다. `storage.ts`가 쓰기 직전에 이미지 데이터 URL을 `Blob`으로 바꾸고 읽은 직후 되돌립니다. `storage.ts` 위쪽은 `Blob`을 보지 않습니다.

스냅샷 저장은 매번 전체 항목을 다시 씁니다. 이름 바꾸기나 아이콘 이동 한 번에 큰 그림을 다시 인코딩하지 않도록, 데이터 URL 문자열을 키로 하는 상한 있는 캐시를 둡니다.

콘텐츠 상한(16MB)은 여전히 모델의 문자열 기준으로 셉니다. 실제로 줄어드는 것은 브라우저 저장소 사용량입니다.

## 20. 키보드 접근성

감사에서 나온 것 중 실제로 조작 불가였던 것들:

시작 버튼이 `onPointerDown`만 듣고 있었습니다. 키보드 활성화는 합성 `click`만 발생시키므로 포커스는 가도 아무 일이 없었습니다. 유일한 우회로였던 검색창 `onFocus`는 Tab이 닿는 순간 시작 메뉴를 열고 포커스를 뺏어가 더 나빴습니다.

`Escape`가 작업 보기와 화면 나누기 후보를 닫지 못했고, 두 오버레이는 포커스가 안으로 들어가지도 않아 자체 `Escape` 핸들러가 발화할 수 없었습니다.

포커스 표시가 사실상 없었습니다. 44개 규칙이 `:focus-visible`에서 `outline: none`을 걸고 배경 틴트로 대체했는데, 그 색이 `:hover`와 같고 다섯 곳에서는 `.is-selected`와도 같았습니다. 전역 링을 두고 틴트는 보조로 내렸습니다.

`useReturnFocus`의 복원은 조건부입니다. 메뉴는 닫히면서 방금 만든 대상(예: 바탕 화면 이름 입력창)에 자리를 넘기는 경우가 많아, 포커스가 실제로 아무 데도 없을 때만 한 프레임 뒤에 되돌립니다.

## 21. role이 약속한 키보드 모델 채우기

`role="menu"`와 `role="grid"`는 Tab만으로는 안 되는 조작을 약속합니다. 화살표로 항목 사이를 옮기고, Home·End로 양 끝으로 뛰고, 위젯 전체가 탭 스톱 하나가 되는 것입니다. 스크린리더는 이 role을 보고 폼 모드로 바꿔 화살표 키를 페이지에 넘기는데, 아무 것도 받지 않으면 일반 버튼보다 나쁩니다.

`src/shell/keyboardNav.ts`가 그 모델을 한 곳에 담습니다.

`handleMenuKeyboard(event, container)`는 DOM에서 `[role^="menuitem"]`을 찾아 움직입니다. 메뉴는 항목을 렌더링하는 모양이 너무 달라서 인덱스로 관리하기 어렵기 때문입니다. 메뉴 14곳이 이 한 줄을 씁니다.

`getNextRovingIndex(key, current, count, columns)`는 순수 함수로 다음 인덱스만 돌려주고 상태는 컴포넌트가 갖습니다. `columns`가 1보다 크면 위·아래가 한 행을 넘고, 행 이동은 감싸지 않고 멈춥니다. 마지막 행에서 아래를 눌렀을 때 반대편 구석으로 순간이동하지 않게 하려는 것입니다.

작업 관리자·이벤트 뷰어·레지스트리 편집기의 그리드는 행마다 탭 스톱이 하나씩 있었습니다. 창 10개가 열린 작업 관리자는 탭 스톱이 10개 늘었습니다. 이제 활성 행만 `tabIndex={0}`을 갖고 나머지는 `-1`이며, 목록이 줄어들면 활성 인덱스를 범위 안으로 당깁니다.

파일 탐색기의 `role="listbox"`는 컨테이너와 항목 버튼이 모두 포커스 가능해 탭 스톱이 N+1개였습니다. 이제 활성 항목이 탭 스톱을 갖고, 항목이 아예 없을 때만 컨테이너가 포커스를 받습니다.

바탕 화면 아이콘을 폴더에 넣는 동작은 포인터 드래그뿐이었습니다. 아이콘 우클릭 메뉴에 **폴더로 이동** 하위 메뉴를 붙여 같은 일을 키보드로 할 수 있게 했습니다.

## 22. 보안: 프레임 탈출과 CSP

`sandbox="allow-scripts allow-same-origin"`은 교차 오리진 사이트에는 문제없지만, **동일 오리진 문서에는 샌드박스가 없는 것과 같습니다.** 프레임이 `parent.document`에 접근해 자기 `sandbox` 속성을 지우고 다시 로드할 수 있습니다.

GitHub Pages는 계정당 오리진이 하나입니다. 이 앱은 `seung-won-yu.github.io/pocket-desk-os/`에서 서비스되고, Edge 시작 화면은 `seung-won-yu.github.io/apple-burst/`를 링크합니다 — 같은 오리진입니다. 주소창에 우리 오리진을 직접 입력해도 같은 상태가 됩니다.

`allow-same-origin`을 빼는 것은 답이 아닙니다. 정상 사이트가 대부분 깨지는데, 그게 이 앱의 기능입니다. 그래서 **동일 오리진 대상은 프레임에 넣지 않고** 이유를 설명하는 안내와 새 탭 링크를 보여줍니다.

CSP는 `<meta>`로 넣습니다. GitHub Pages는 정적 파일만 주므로 응답 헤더를 설정할 수 없습니다. 프로덕션 빌드에만 적용합니다 — 개발 서버는 인라인 `<style>`과 HMR을 쓰는데 이 정책이 그것을 막습니다.

`frame-src`는 넓게 둘 수밖에 없습니다(임의 사이트 표시가 기능이니까). 대신 `https:`로 한정해 `data:`·`blob:` 문서는 프레임에 들어올 수 없게 했습니다. `connect-src`는 Edge가 실제로 호출하는 리더 프록시만 허용합니다.

## 23. 실제 로컬 폴더는 로컬 전용이다

File System Access API는 조용한 접근을 막습니다. 사용자 제스처가 필요하고, 경로를 페이지가 지정할 수 없고, 쓰기는 별도 프롬프트이며, 권한은 탭과 함께 사라집니다.

**막지 못하는 것은 앱 자체가 장악되는 경우입니다.** 스크립트 주입, 침해된 의존성, 유출된 배포 토큰 중 무엇이든 성공하면 승인된 핸들을 그대로 물려받습니다. 이 앱은 이미 외부 요청(리더 프록시)을 하므로 읽은 것을 내보낼 경로도 있습니다. 사고의 최대 피해가 "가상 파일 날아감"에서 "실제 문서 유출"로 올라갑니다.

그래서 `isLocalFolderAccessAvailable()`이 `localhost`·`127.0.0.1`·`[::1]`에서만 참을 돌려줍니다. 공개 배포본에는 버튼이 아예 렌더링되지 않습니다. 같은 빌드 결과물을 두 오리진에서 띄워 확인했습니다 — 공개 오리진 0개, localhost 2개.

가져오기는 추가로 걸러냅니다. `.env`·`id_rsa`·`*.pem`·`credentials` 같은 이름은 **읽지 않고 건너뜁니다.** 사용자가 폴더를 허락했더라도 비밀을 브라우저 저장소로 복사하지 않습니다. `.git`·`.ssh`·`node_modules`·`Library` 등은 순회하지 않고, 항목 수·바이트·깊이에 상한이 있으며, 핸들은 보관하지 않습니다.

**실행은 불가능합니다.** 브라우저에 프로세스 모델이 없어 `codex`·`git`·`npm`이나 어떤 바이너리도 돌릴 수 없습니다. 파일 바이트를 읽고 쓰는 것까지입니다.
